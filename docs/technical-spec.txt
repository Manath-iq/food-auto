Техническое задание: функционал кулинарного приложения
Этап 1 — функциональность
1. Общая концепция приложения
Приложение должно помогать пользователю организовывать домашнее питание: находить рецепты, составлять меню на несколько дней или недель, планировать покупки, учитывать продукты дома и получать рекомендации от искусственного интеллекта.
Основная задача — объединить несколько процессов в одном приложении:
Поиск и просмотр рецептов.
Планирование питания.
Автоматическое формирование списка покупок.
Учёт продуктов в домашнем холодильнике.
Подбор блюд на основе имеющихся продуктов.
Помощь ИИ в приготовлении и планировании питания.
Все разделы должны быть взаимосвязаны. Например, если пользователь добавил рецепт в план питания, необходимые ингредиенты должны автоматически учитываться при формировании списка покупок.
2. Главная страница
Назначение: каталог рецептов, через который пользователь находит интересующие его блюда.
2.1. Поиск рецептов
В верхней части страницы расположена поисковая строка.
Функции:
Поиск по названию блюда.
Поиск по ингредиентам.
Поиск по типу блюда.
Поиск по ключевым словам.
Отображение подходящих результатов по мере ввода текста.
Возможность очистить поисковую строку.
Пример: пользователь вводит «курица, сыр, помидоры», приложение показывает рецепты, в которых используются эти ингредиенты.
2.2. Категории рецептов
На главной странице размещаются горизонтальные блоки с категориями.
Примеры:
Новые рецепты.
Завтраки.
Обеды.
Ужины.
Салаты и боулы.
Супы.
Основные блюда.
Гарниры.
Десерты.
Выпечка.
Перекусы.
Напитки.
Каждая категория имеет кнопку «Все», которая открывает отдельную страницу со всеми рецептами данной категории.
2.3. Карточки рецептов
Каждая карточка содержит:
Фотографию готового блюда.
Название.
Время приготовления.
Калорийность одной порции.
Кнопку добавления в избранное.
Кнопку быстрого добавления в план питания.
При нажатии на карточку открывается подробная страница рецепта.
2.4. Фильтрация рецептов
Пользователь должен иметь возможность фильтровать рецепты по следующим параметрам:
Время приготовления.
Калорийность.
Тип блюда.
Основной ингредиент.
Стоимость приготовления.
Сложность.
Количество ингредиентов.
Диетические особенности.
Дополнительно:
Без мяса.
Без молочных продуктов.
Без глютена.
Высокобелковые блюда.
Низкокалорийные блюда.
Фильтры можно комбинировать.
2.5. Избранное
Пользователь может сохранять понравившиеся рецепты в избранное.
Отдельная подборка должна содержать все сохранённые блюда с возможностью удаления и добавления в меню.
3. Страница рецепта
Это одна из важнейших страниц приложения.
При открытии рецепта пользователь должен видеть полную информацию о приготовлении блюда.
3.1. Основная информация
Название блюда.
Большая фотография.
Краткое описание.
Время приготовления.
Количество порций.
Сложность приготовления.
Калорийность.
Белки, жиры и углеводы.
3.2. Ингредиенты
Список всех необходимых продуктов.
Для каждого ингредиента указывается:
Название.
Количество.
Единица измерения (граммы, миллилитры, штуки и т. д.).
Важная функция — изменение количества порций.
Если рецепт рассчитан на 2 порции, пользователь может переключить его на 4 или 6 порций.
Все количества ингредиентов автоматически пересчитываются пропорционально.
3.3. Приготовление
Инструкция должна быть разделена на последовательные шаги.
Каждый шаг может содержать:
Текст инструкции.
Фотографию или видео.
Время выполнения, если применимо.
Температуру приготовления, если необходимо.
Дополнительные функции:
Кнопка «Следующий шаг».
Кнопка «Предыдущий шаг».
Таймер приготовления.
Возможность отметить выполненный шаг.
Голосовое сопровождение инструкции (можно добавить позднее).
3.4. Действия с рецептом
На странице должны быть кнопки:
Добавить в избранное.
Добавить в меню.
Добавить ингредиенты в список покупок.
Проверить наличие ингредиентов в холодильнике.
Изменить количество порций.
Поделиться рецептом.
3.5. Комментарии и заметки
Пользователь может оставлять личные заметки к рецепту.
Например:
В следующий раз добавить меньше соли.
Готовить на 5 минут дольше.
Вместо сливок использовать молоко.
Также желательно предусмотреть возможность создания собственного рецепта с фотографией, ингредиентами и инструкцией.
4. Страница «Меню» — план питания
Назначение: составление расписания питания на каждый день и неделю.
Это не просто календарь, а конструктор меню.
4.1. Переключение дат
В верхней части страницы отображается выбранная дата.
Пользователь может:
Переключаться между днями.
Выбирать конкретную дату через календарь.
Просматривать меню на неделю.
Возвращаться к сегодняшнему дню.
4.2. Режимы отображения
Два режима:
День — подробный план питания на выбранную дату.
Неделя — общее расписание питания на семь дней.
4.3. Приёмы пищи
В дневном режиме отображаются отдельные блоки:
Завтрак.
Второй завтрак.
Обед.
Полдник.
Ужин.
Дополнительный приём пищи.
Каждый блок раскрывается и сворачивается.
Внутри блока пользователь может размещать несколько рецептов.
Например, обед:
Куриный суп.
Овощной салат.
Хлеб.
4.4. Добавление блюд в меню
Предусмотреть несколько способов:
Перетащить карточку рецепта с главной страницы в нужный приём пищи.
Нажать кнопку «+» внутри приёма пищи и выбрать рецепт.
Добавить блюдо непосредственно со страницы рецепта.
Выбрать блюдо из избранного.
После добавления блюда оно должно появиться в соответствующем приёме пищи.
Пользователь может:
Удалить блюдо.
Заменить блюдо.
Изменить количество порций.
Переместить блюдо в другой приём пищи.
Скопировать меню на другой день.
4.5. Подсчёт КБЖУ
Приложение автоматически рассчитывает пищевую ценность всех добавленных блюд.
В верхней части страницы отображаются:
Общая калорийность.
Белки.
Жиры.
Углеводы.
Все показатели пересчитываются при добавлении, удалении или изменении количества порций.
В недельном режиме можно показывать показатели отдельно за каждый день и средние значения за неделю.
4.6. Автоматическое составление меню
Добавить функцию автоматического формирования меню с помощью ИИ.
Пользователь задаёт:
Количество дней.
Количество приёмов пищи.
Желаемую калорийность.
Предпочтения в еде.
Исключённые продукты.
Бюджет (опционально).
ИИ подбирает рецепты из каталога и формирует готовое расписание.
Пользователь может принять всё меню или заменить отдельные блюда.
Важно: автоматически созданное меню не должно сохраняться без подтверждения пользователя.
5. Страница «Корзина» — список покупок
Назначение: автоматическое формирование списка продуктов, необходимых для приготовления запланированных блюд.
Одна из ключевых особенностей приложения — связь корзины с планом питания.
5.1. Автоматическая генерация списка
После составления меню на определённый период приложение анализирует все рецепты и собирает необходимые ингредиенты.
Например:
Пользователь запланировал:
Понедельник: курицу с рисом.
Вторник: куриный суп.
Среда: пасту с курицей.
Приложение объединяет одинаковые продукты и суммирует их количество.
Вместо трёх отдельных позиций пользователь получает одну:
Куриное филе — 900 г.
5.2. Учёт имеющихся продуктов
Перед добавлением продуктов в корзину приложение должно проверять домашние запасы.
Например:
Для меню требуется 1 кг картофеля.
В холодильнике уже есть 400 г.
В корзину добавляется только 600 г.
Пользователь может изменить это количество вручную.
5.3. Категории продуктов
Список автоматически распределяется по категориям:
Мясо и птица.
Рыба и морепродукты.
Овощи.
Фрукты и ягоды.
Молочные продукты.
Бакалея.
Крупы и макароны.
Хлеб и выпечка.
Замороженные продукты.
Соусы и специи.
Прочее.
Соль, перец и вода, как на твоём примере, по умолчанию не добавляются в список.
Но пользователь должен иметь возможность изменить это правило.
5.4. Ручное добавление
Отдельная кнопка «+» позволяет самостоятельно добавить продукт.
Поля:
Название.
Количество.
Единица измерения.
Категория.
5.5. Работа со списком
Отмечать купленные продукты.
Удалять позиции.
Изменять количество.
Добавлять новые позиции.
Очищать список.
Возвращать случайно удалённые позиции.
Сортировать по категориям.
Дополнительно: возможность делиться списком покупок с другим человеком по ссылке.
5.6. Планирование покупок на две недели
По умолчанию приложение должно поддерживать генерацию списка на ближайшие 14 дней.
Пользователь также может выбрать другой период: 1 день, 3 дня, неделю или произвольный диапазон дат.
6. Страница «Мой холодильник»
Назначение: учёт продуктов, которые уже имеются дома.
Эта функция должна быть связана с корзиной, рецептами и ИИ-помощником.
6.1. Добавление продуктов
Пользователь может добавить продукты несколькими способами:
Способ 1. Ручной ввод
Пользователь вводит название продукта в поисковую строку.
Способ 2. Выбор из каталога
Приложение предлагает подходящие варианты продуктов.
Способ 3. Добавление фотографией
Пользователь фотографирует продукты, а ИИ распознаёт их и предлагает добавить в холодильник.
Перед сохранением пользователь подтверждает распознанные позиции.
Способ 4. Добавление из корзины
После покупки пользователь может перенести купленные продукты в холодильник одним действием.
6.2. Информация о продукте
Для каждого продукта сохраняются:
Название.
Количество.
Единица измерения.
Дата добавления.
Срок годности (если известен).
Категория.
Дополнительная заметка.
6.3. Контроль сроков годности
Приложение отслеживает сроки годности и показывает уведомления:
Скоро истекает срок годности.
Срок годности истекает сегодня.
Срок годности истёк.
Пользователь должен иметь возможность самостоятельно указывать и изменять сроки.
6.4. Удаление и изменение продуктов
Можно:
Удалить продукт.
Изменить его количество.
Указать, что продукт закончился.
Изменить срок годности.
Переместить продукт в другую категорию.
При приготовлении блюда приложение может предложить списать использованные ингредиенты из холодильника. Списание должно происходить после подтверждения пользователя.
6.5. Подбор рецептов из холодильника
Это особенно полезная функция.
Приложение анализирует продукты пользователя и предлагает рецепты, которые можно приготовить.
Например, дома есть:
Яйца.
Помидоры.
Сыр.
Молоко.
Мука.
Приложение предлагает блюда из этих ингредиентов.
При этом нужно предусмотреть три варианта подбора:
Рецепты, для которых есть абсолютно все продукты.
Рецепты, для которых не хватает максимум 1–2 ингредиентов.
Рецепты, которые используют максимальное количество продуктов из холодильника.
Также можно добавить фильтр «Сначала использовать продукты с истекающим сроком годности».
7. Центральная кнопка — ИИ-помощник
Я предлагаю сделать её отдельным полноценным разделом.
Это интеллектуальный помощник, который понимает запросы пользователя и умеет взаимодействовать с остальными разделами приложения.
7.1. Генерация рецептов
Пользователь может написать:
«Придумай мне ужин из курицы и овощей, чтобы приготовление заняло не больше 30 минут».
ИИ должен:
Подобрать подходящее блюдо.
Сформировать список ингредиентов.
Рассчитать количество продуктов.
Указать КБЖУ.
Составить пошаговую инструкцию.
Предложить фотографию блюда.
Пользователь может сохранить результат как новый рецепт.
7.2. Изменение рецептов
Примеры запросов:
Замени сливки на менее калорийный продукт.
Сделай рецепт более белковым.
Убери лук.
Рассчитай ингредиенты на 5 человек.
Предложи более бюджетную версию.
ИИ должен учитывать изменения и пересчитывать КБЖУ.
7.3. Работа с холодильником
Примеры:
Что приготовить из того, что у меня есть?
Какие продукты скоро испортятся?
Что можно приготовить из оставшегося риса?
Как использовать продукты, которые остались после недели?
ИИ получает доступ к актуальному списку продуктов пользователя.
7.4. Работа с меню
Примеры:
Составь меню на неделю.
Замени завтрак в среду.
Сделай ужины разнообразнее.
Уменьши стоимость меню.
Подбери меню с учётом моих предпочтений.
ИИ должен иметь возможность предлагать изменения, но не менять сохранённое меню без подтверждения.
8. Дополнительные функции, которые я рекомендую добавить
Это функции, которые могут сделать приложение заметно полезнее обычного сборника рецептов.
1. Умные таймеры
Возможность запускать таймер прямо из рецепта. Несколько таймеров могут работать одновременно.
2. Учёт стоимости питания
Пользователь может указывать цены на продукты. Приложение рассчитывает стоимость каждого блюда, порции и всего меню.
3. Собственные рецепты
Возможность создавать личные рецепты, загружать фотографии и сохранять семейные блюда.
4. Повторное использование меню
Можно сохранить понравившееся меню и использовать его повторно через неделю или месяц.
5. Исключение аллергенов и нежелательных продуктов
Пользователь задаёт продукты, которые нельзя или не хочется использовать. Система учитывает это при поиске и генерации рецептов.
6. История приготовлений
Приложение запоминает приготовленные блюда, позволяет повторять их и оставлять оценки.
9. Профиль пользователя и настройки
Отдельная страница профиля должна содержать:
Имя пользователя.
Фотографию профиля.
Избранные рецепты.
Собственные рецепты.
Историю приготовлений.
Сохранённые меню.
Пищевые предпочтения.
Исключённые продукты.
Настройки уведомлений.
Настройки единиц измерения.
Управление аккаунтом.
Дополнительно можно предусмотреть синхронизацию данных между устройствами.
10. Как все страницы взаимодействуют между собой
Это очень важная часть разработки. Приложение не должно состоять из пяти независимых страниц.
Вот основная логика:
Главная — каталог рецептов
Поиск, выбор и просмотр блюд
Меню — план питания
Распределение блюд по дням и приёмам пищи
Корзина — список покупок
Расчёт необходимых продуктов с учётом запасов
Холодильник — домашние запасы
Учёт купленных продуктов и их остатков
ИИ-помощник
Работает со всеми разделами и помогает управлять ими
11. Что должен предусмотреть программист технически
Чтобы приложение работало корректно, необходимо предусмотреть:
Регистрацию и авторизацию пользователей.
Индивидуальное хранение данных каждого пользователя.
Базу данных рецептов и ингредиентов.
Хранение фотографий блюд.
Систему категорий и поиска.
Сохранение меню и календаря питания.
Автоматический расчёт КБЖУ.
Автоматическое формирование списка покупок.
Связь списка покупок с холодильником.
Интеграцию с ИИ для генерации и изменения рецептов.
Синхронизацию данных с сервером.
Возможность редактирования рецептов и продуктов.
Обработку ошибок и проверку вводимых данных.
Особенно важно правильно организовать базу ингредиентов: один и тот же продукт должен иметь единое название и идентификатор, чтобы приложение могло объединять его в рецептах, меню, корзине и холодильнике.
12. Приоритеты разработки

Рецепты должны заранее загружаться в базу данных и распределяться по категориям.

14.2. Рецепты, создаваемые искусственным интеллектом
ИИ должен уметь создавать совершенно новые рецепты, которых ещё нет в базе.
Пример запроса:
«Придумай вкусный завтрак из яиц, творога и помидоров. Не больше 400 ккал, приготовление до 15 минут».
ИИ должен сформировать полноценный рецепт:
Название блюда.
Краткое описание.
Фотографию или визуализацию готового блюда.
Список ингредиентов с точными количествами.
Количество порций.
Время приготовления.
Подробную инструкцию.
Калорийность.
Белки, жиры и углеводы.
Возможные замены ингредиентов.
После генерации пользователь может:
Сохранить рецепт в свою библиотеку.
Добавить его в избранное.
Добавить в план питания.
Отправить ингредиенты в корзину.
Изменить рецепт.
Попросить ИИ создать другую версию.
Важное техническое требование: созданные ИИ рецепты должны сохраняться в базе данных только после подтверждения пользователя. Повторная генерация похожего блюда не должна создавать бесконечные дубликаты.
14.3. Проверка рецептов
ИИ не должен выдавать случайный набор продуктов за полноценный рецепт.
Необходимо предусмотреть проверку:
Сочетаемости ингредиентов.
Корректности количества продуктов.
Реалистичности времени приготовления.
Последовательности действий.
Безопасности приготовления мяса, рыбы и яиц.
Соответствия рассчитанного КБЖУ ингредиентам.
Если ИИ не уверен в точности какого-либо значения, он должен обозначать его как приблизительное.

Пошаговая инструкция.
Пользователь может добавлять любое количество ингредиентов и шагов приготовления.
15.2. Автоматический расчёт КБЖУ
После внесения ингредиентов приложение самостоятельно рассчитывает пищевую ценность рецепта.
Пользователю не нужно вручную вводить калорийность каждого продукта.
Алгоритм:
Пользователь добавляет ингредиент.
Приложение находит соответствующий продукт в базе пищевой ценности.
Получает его калорийность и БЖУ на 100 г.
Пересчитывает показатели с учётом количества.
Складывает показатели всех ингредиентов.
Рассчитывает пищевую ценность всего блюда и одной порции.
Если ингредиент не найден, приложение предлагает выбрать похожий продукт или добавить его пищевую ценность вручную.
15.3. Распознавание рецепта по фотографии или тексту
Дополнительная очень полезная функция.
Пользователь может загрузить:
Фотографию страницы старой кулинарной книги.
Скриншот рецепта из интернета.
Фотографию рукописной записи.
Текст рецепта.
ИИ распознаёт информацию и автоматически заполняет форму создания рецепта.
Пользователь проверяет распознанные ингредиенты и количества, после чего сохраняет рецепт.
15.4. Редактирование собственных рецептов
В любой момент пользователь может:
Изменить название.
Заменить фотографию.
Добавить или удалить ингредиент.
Изменить количество.
Изменить инструкцию.
Изменить количество порций.
После каждого изменения КБЖУ пересчитывается автоматически.
16. Система расчёта калорий и БЖУ
Критически важная функция
Расчёт пищевой ценности должен быть частью всей системы, а не отдельным необязательным инструментом.
Он должен работать:
В каталоге рецептов.
На странице каждого блюда.
При создании собственного рецепта.
При генерации рецепта ИИ.
В дневном и недельном меню.
При изменении количества порций.
При замене ингредиентов.
16.1. Источник данных о продуктах
Необходимо использовать структурированную базу пищевой ценности продуктов.
Для каждого продукта должны храниться:
Калорийность на 100 г.
Белки на 100 г.
Жиры на 100 г.
Углеводы на 100 г.
Название.
Категория.
Состояние продукта (сырой, варёный, жареный и т. д.).
Желательно предусмотреть возможность подключения внешней базы пищевой ценности и дополнения её собственной базой.
Приоритет источников:
Данные с упаковки конкретного продукта, если пользователь их указал.
Проверенная база пищевой ценности.
Расчётные значения для продуктов без точных данных.
Оценка ИИ — только когда более точных данных нет.
16.2. Формула расчёта
Для каждого ингредиента:
Ккал = \frac{Масса \times Ккал_{100г}}{100}
Аналогично рассчитываются белки, жиры и углеводы.
Затем показатели всех ингредиентов суммируются.

16.3. Учет готового веса блюда
Очень важно!
Масса продуктов до приготовления и масса готового блюда могут значительно отличаться.
Например:
100 г сухого риса после варки могут весить около 280–300 г.
Мясо теряет часть массы при приготовлении.
Овощи могут терять воду.
Поэтому нужно предусмотреть два показателя:
Пищевая ценность всего рецепта.
Пищевая ценность на 100 г готового блюда.
Для этого при создании рецепта желательно указывать фактический вес готового блюда. Если он неизвестен, система должна показывать расчётную оценку и не выдавать её за точное измерение.
16.4. Замена ингредиентов
Если пользователь заменяет ингредиент, приложение автоматически пересчитывает КБЖУ.
Например:
«Замени сливки 20% на молоко 2,5%».
Приложение:
Удаляет прежний ингредиент.
Добавляет новый.
Сохраняет количество или предлагает подходящее количество для замены.
Пересчитывает калорийность.
Обновляет БЖУ.
16.5. Точность расчётов
Необходимо разделять:
Точные значения из базы.
Расчётные значения.
Приблизительные значения, полученные ИИ.
Не следует показывать пользователю чрезмерную точность там, где исходные данные приблизительные.
17. ИИ-помощник: расширенная система управления приложением
ИИ должен быть не просто чатом, который отвечает на вопросы. Он должен иметь возможность выполнять действия внутри приложения.
17.1. Общение с пользователем
Пользователь может писать запросы обычным языком, без специальных команд.
Например:
«Что приготовить сегодня?»
«Составь меню на неделю».
«У меня осталась курица, придумай ужин».
«Найди что-нибудь сладкое, но не слишком калорийное».
«Замени завтрашний обед».
«Что нужно купить на выходные?»
ИИ должен понимать контекст и учитывать информацию, которая уже есть в приложении.
17.2. Управление меню
ИИ должен уметь:
Создавать меню на выбранный период.
Добавлять блюда в конкретный день.
Удалять блюда.
Заменять отдельные приёмы пищи.
Переносить блюда между днями.
Пересчитывать количество продуктов.
Формировать список покупок после изменения меню.
Пример:
Пользователь: «Замени ужин в четверг на что-нибудь с рыбой».
ИИ предлагает несколько вариантов, показывает их КБЖУ и после выбора пользователя обновляет меню.
17.3. Управление холодильником
ИИ должен получать актуальную информацию о продуктах пользователя.
Он может:
Предлагать рецепты из имеющихся запасов.
Находить продукты, которые скоро испортятся.
Подсказывать, чего не хватает для рецепта.
Предлагать способы использовать остатки продуктов.
Добавлять необходимые ингредиенты в корзину.
17.4. Управление корзиной
Примеры:
«Добавь всё необходимое для приготовления борща».
«Удали из корзины молоко, я уже купила его».
«Составь список покупок на следующие две недели».
ИИ должен выполнять соответствующие действия и сообщать пользователю, что именно изменилось.

18. Система персональных предпочтений
Приложение должно постепенно адаптироваться под привычки пользователя.
В профиле необходимо предусмотреть настройки:
Любимые продукты.
Нелюбимые продукты.

Предпочитаемые кухни мира.

22. Дополнительные требования к логике приложения
Это технические требования, которые важно не упустить.
Все действия пользователя должны автоматически сохраняться на сервере.
При закрытии приложения пользователь не должен терять меню, рецепты, корзину или продукты.
Изменения должны синхронизироваться между устройствами.
Удаление рецепта из избранного не должно удалять сам рецепт из базы.
Удаление блюда из меню не должно автоматически удалять его из избранного.
Если один продукт используется в нескольких рецептах, система должна распознавать его как один и тот же ингредиент.
При изменении меню список покупок должен обновляться с учётом уже купленных продуктов.
При изменении рецепта ранее сохранённые пользователем меню не должны неожиданно изменяться. Нужно сохранять версию рецепта или фиксировать его состав на момент добавления.
ИИ не должен самостоятельно удалять пользовательские данные.
При ошибке сервера или ИИ пользователь должен получить понятное сообщение, а введённая информация не должна теряться.
